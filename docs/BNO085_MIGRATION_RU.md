# Переход робота на BNO085

Установлен BNO085, проверенный пользователем на Arduino при I²C 100 кГц.
Переход на MOLA/одометрию без IMU **не выполняется**. Сохраняются VESC-счётчики,
IMU-курс, `/odometry/local`, GPS EKF и проверки свежести датчиков.

## Что изменилось

- ROS/Python пакет `bno086_imu` заменён нейтральным `bno08x_imu`.
- Node `/imu/bno08x_imu`, YAML selector `/**/bno08x_imu`.
- Исполняемый файл остаётся `imu_node`; диагностика — `bno08x_diagnose`.
- Обновлены зависимости, hardware launch, руководства и тесты.
- SH-2/SHTP сообщения общие для BNO085/BNO086. Декодируется Product ID и выводится
  версия/номер ПО, без предположения, что номер ПО однозначно определяет модель.
- Никаких fake IMU, отключения watchdog или авто-возобновления после reset.

## Подключение

| BNO085 | Pi BCM | Физический пин |
|---|---|---|
| SDA | GPIO2 | 3 |
| SCL | GPIO3 | 5 |
| RST | GPIO17 | 11 |
| INT | GPIO27 (только вход Pi!) | 13 |
| 3V3 | питание 3,3 В | 1 |
| GND | земля | 6 |

Монтировать при выключенном питании. PS0/PS1 и адрес — по документации новой
платы. Проверить отсутствие конфликтов с UART overlays. Не применять `gpioset`
к INT и не подавать 5 В на сигналы.

## Частота 100 кГц и адрес

В активной секции `[all]` `/boot/firmware/config.txt` должны быть:

```ini
dtparam=i2c_arm=on
dtparam=i2c_arm_baudrate=100000
```

Сделать резервную копию перед правкой, проверить последующие overrides/includes,
сохранить UART-настройки. После изменения перезагрузить Pi. Шаблон включён в
`src/bno08x_imu/config/pi5_i2c_100khz.txt`. 100 кГц — частота шины; `rate_hz: 25.0`
в YAML — частота отчётов датчика. ROS-драйвер не перепрограммирует clock адаптера.

**Адрес новой платы пользователь ещё не сообщил.** В конфигурации сохранено
75 (0x4B), но это не гарантированный default для BNO085. Перенести адрес из
успешного Arduino-скетча: 0x4A → 74, 0x4B → 75. Автовыбор/сброс обоих адресов
в рабочем драйвере не применяется. Стендовая утилита может проверить оба.

## Сборка и запуск

Остановить старые launch и процессы, отключить приводы. Открыть новый терминал,
где не подключён старый overlay (проверить также автозагрузку `.bashrc`).

```bash
cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
sudo apt install python3-smbus2 python3-libgpiod gpiod
colcon build --symlink-install --packages-up-to project_start
source install/setup.bash
# Пример для 0x4B; если Arduino использовал 0x4A, заменить 75 на 74:
ros2 launch bno08x_imu imu.launch.py \
  i2c_bus:=1 i2c_address:=75 gpio_chip:=auto rst_gpio:=17 int_gpio:=27
```

В старой install-директории может остаться прежний пакет. Не запускать его:
уникальное имя нового пакета не даёт выбрать его случайно через новый launch.
Для полной очистки старых артефактов предпочтительна сборка в новом workspace;
не удалять весь workspace ради переименования.

После отдельной проверки остановить IMU launch и запустить hardware:

```bash
ros2 launch project_start start.launch.py \
  imu_i2c_bus:=1 imu_i2c_address:=75 \
  imu_gpio_chip:=auto imu_rst_gpio:=17 imu_int_gpio:=27
```

Не запускать оба launch одновременно. Магнитное склонение задать местное через
`declination_deg`; не переносить калибровку или mounting yaw со старой платы вслепую.
`base_link → imu_link` в URDF проверить по новой ориентации/положению платы:
кватернион и гироскоп представлены в осях датчика, коррекцию делает одометрия по TF.

## Приёмка

- Сначала проверить Product ID, затем `/imu/data`, `/imu/accuracy`, `/diagnostics`.
- В `/imu/data` ожидаются новые accel/gyro/Rotation Vector с accuracy >= 2,
  поэтому данные могут отсутствовать до калибровки. Это не повод понижать защиту.
- Проверить стороны света, знак поворота, монтаж, курс с включёнными моторами.
- Остановить IMU на стенде: локальная одометрия и AUTO должны отказать безопасно.
- После reset/ошибки перезапускать hardware/localization/navigation на стоянке,
  не продолжать старую миссию. Драйвер не публикует TF; владелец монтажа — URDF/RSP.

Стендовая диагностика без ROS:

```bash
PYTHONPATH="$PWD/src/bno08x_imu" /usr/bin/python3 -u -m bno08x_imu.diagnose \
  --confirm-stationary --i2c-bus 1 --rst-gpio 17 --int-gpio 27
```

Работа этой платы на Arduino не доказывает совместимость timing с ядром Pi.
В среде разработки нет ROS/датчика: автоматические проверки — офлайн,
аппаратная приёмка BNO085 на Pi остаётся обязательной.
