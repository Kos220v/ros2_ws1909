# BNO086 Qwiic → Raspberry Pi 5 по I²C

Инструкция для **SparkFun VR IMU Breakout – BNO086 (Qwiic)**, Raspberry Pi 5,
Ubuntu 24.04 и ROS 2 Jazzy. Пакет проекта: `bno086_imu`.

> Подключать только при отключённом питании Pi и платы. На первом запуске
> отключить силовую часть приводов. Не считать появление quaternion разрешением
> на автономное движение: сначала проверить оси, абсолютный курс и отказы.

## 1. Что изменено в проекте

- Полностью удалён старый пакет `imu_stm32_bridge`, его UART-протокол, сервисы,
  udev-правила и инструкции. Контроллер STM32F303 больше не нужен для IMU.
- Новый ROS-узел `/imu/bno086_imu` напрямую читает BNO086 через `/dev/i2c-N`.
- Сохранены `/imu/data`, `/imu/mag`, `/imu/azimuth`, `imu_link`.
  Поэтому входы EKF и navsat_transform менять на новые имена не требуется.
- Добавлены `/imu/accuracy` и диагностика качества/свежести.
- Общий запуск `project_start/start.launch.py` использует BNO086; UART AMA1
  освобождён. Аргумент `imu_port` больше не поддерживается.
- Калибровкой/fusion занимается SH-2 внутри BNO086, а не прошивка внешнего MCU.
  Это не устраняет магнитные помехи и ошибки механического монтажа.

## 2. Провода: только 3,3 В

Нужен Qwiic→четыре отдельных провода, подходящий Qwiic HAT либо пайка к площадкам
3V3/GND/SDA/SCL на плате, **плюс два отдельных провода RST и INT**. У Raspberry Pi 5 нет встроенного Qwiic-разъёма.
Использовать один из двух Qwiic-разъёмов BNO086; они подключены к одной шине.

| Сигнал BNO086 / Qwiic | Raspberry Pi 5 | **Физический контакт** 40-pin |
|---|---|---:|
| `3V3` | 3,3 В | **1** (альтернатива 17) |
| `GND` | Земля | **6** (или другой GND) |
| `SDA` | **GPIO2**, SDA1 | **3** |
| `SCL` | **GPIO3**, SCL1 | **5** |
| `RST` | **GPIO17**, выход Pi, LOW = reset | **11** |
| `INT` | **GPIO27**, вход Pi, LOW = готовность | **13** |

```text
Raspberry Pi 5                      SparkFun BNO086 Qwiic
pin 1  (3V3)  --------------------  3V3
pin 6  (GND)  --------------------  GND
pin 3  (GPIO2 / SDA1) ------------  SDA
pin 5  (GPIO3 / SCL1) ------------  SCL
pin 11 (GPIO17) -----------------  RST
pin 13 (GPIO27) -----------------  INT
```

**GPIO2 — это НЕ физический контакт 2!** Физические контакты 2 и 4 имеют **5 В**;
к этой плате их не подключать. У BNO086 breakout питание и VDDIO связаны;
5 В на питание/линию данных может повредить датчик и Pi.

У стандартного Qwiic-кабеля обычно чёрный=GND, красный=3V3, синий=SDA,
жёлтый=SCL. Цвет не является гарантией у переходников: проверить подписи,
распиновку производителя и при необходимости прозвонить **до** включения.
Не ориентироваться на фотографию разъёма без учёта стороны просмотра.

**RST и INT обязательны в этой реализации.** SparkFun сообщает, что начиная с
Arduino-библиотеки v1.0.3 одного I²C недостаточно для надёжной работы:
[Hardware Hookup](https://docs.sparkfun.com/SparkFun_VR_IMU_Breakout_BNO086_QWIIC/hardware_hookup/#connecting-via-qwiic-port-reset-interrupt-pins).
Драйвер использует libgpiod, физический LOW для обоих активных сигналов, внутреннюю
подтяжку INT вверх. RST при захвате сразу HIGH, затем LOW 10 мс и HIGH, ожидание
старта 300 мс и INT до 2 с. Проверяется **уровень**, не только фронт INT: уже
активный LOW не теряется. INT проверяется перед новым пакетом, не между чтением
его заголовка и тела. Это опрос GPIO каждые 10 мс, не timestamp IRQ измерения.
`WAK` и `BOOT` остаются на штатных подтяжках платы; BOOT не замыкать на землю.

GPIO17/27 — предлагаемые **BCM** номера только при свободных линиях! Проверить
UART overlays, HAT и другие потребители. В проекте используются несколько UART;
их ttyAMA-номера не доказывают отсутствие конфликта пинов. При наличии утилиты
`pinctrl` проверить `pinctrl get 17 27`; также проверить boot config и `gpioinfo`.
Если линии заняты — сначала согласовать другую пару свободных пинов и параметры,
не отключать защиту эксклюзивного захвата. Проводку менять без питания.

### Перемычки и адрес

Для заводской SparkFun BNO086:

- I²C выбран по умолчанию: PS0=0, PS1=0 (перемычки открыты).
- Адрес по умолчанию **0x4B** = **75** в десятичной записи.
- Альтернативный адрес **0x4A** = **74**, после изменения ADR по инструкции платы.
- После изменения PS/ADR полностью выключить и включить питание.
- На странице SparkFun в описании ADR встречается противоречивая запись `0x48`;
  раздел I²C указывает 0x4B/0x4A. Для драйвера используйте реально обнаруженный
  адрес 0x4A либо 0x4B, а не слепо переносите опечатку. Другая ревизия/клон требует
  проверки схемы именно вашей платы.

Плата имеет подтяжки SDA/SCL 2,2 кОм к 3,3 В; на Pi также есть подтяжки.
Не добавляйте ещё резисторы автоматически и не подключайте подтяжки к 5 В.
При нескольких модулях проверяйте суммарное сопротивление, ток низкого уровня
и фронты; при необходимости отключать дублирующие подтяжки по схеме платы.
Начните с короткого кабеля (например, 10–20 см), без Qwiic-мультиплексора,
вдали от проводов двигателя. I²C — не интерфейс для длинного жгута через весь робот.

## 3. Включить I²C на Ubuntu 24.04 / Pi 5

Прежде чем менять конфигурацию, убедитесь, что GPIO2/GPIO3 не заняты существующим
UART overlay, HAT или другим интерфейсом. **Имена ttyAMA не задают GPIO однозначно**.
Освобождение старого UART IMU не гарантирует отсутствие конфликтов на GPIO2/3.

```bash
sudo cp /boot/firmware/config.txt /boot/firmware/config.txt.before-bno086
sudo nano /boot/firmware/config.txt
```

В подходящей активной секции (обычно `[all]`) обеспечить единственную действующую
настройку, без последующего переопределения:

```ini
[all]
dtparam=i2c_arm=on
dtparam=i2c_arm_baudrate=100000
```

Начальный профиль — **100 кГц**, отчёты IMU 25 Гц / magnetometer 10 Гц.
BNO086 поддерживает I²C до 400 кГц, но начинать сразу с максимума не обязательно.
Не отключайте все UART overlays: ELRS, GNSS и VESC по-прежнему их используют.
Уберите только ненужную настройку старого IMU, если она была отдельной, и проверьте
порты остальных устройств после reboot: их нумерация может измениться.

```bash
sudo apt update
sudo apt install i2c-tools python3-smbus2
sudo modprobe i2c-dev
# Подгружать i2c-dev после перезагрузки:
echo i2c-dev | sudo tee /etc/modules-load.d/i2c-dev.conf
sudo reboot
```

На Raspberry Pi OS I²C также можно включить через `raspi-config`, но на Ubuntu
не следует предполагать наличие этой утилиты. После перезагрузки:

```bash
i2cdetect -l
ls -l /dev/i2c-*
```

Обычно SDA1/SCL1 соответствуют `/dev/i2c-1`. Если ядро/overlay создаёт другой
номер, сначала установите, какой адаптер связан с контактами 3/5, и задайте его
в launch. Не перебирайте все I²C-шины Pi сканированием: часть обслуживает системные
устройства и разъёмы камер/дисплеев.

### Доступ без sudo

```bash
sudo groupadd -f i2c
sudo usermod -aG i2c "$USER"
ls -l /dev/i2c-1
```

Ожидается группа `i2c` и доступ чтение/запись для неё. Если правило не установлено
дистрибутивом, создайте:

```bash
echo 'SUBSYSTEM=="i2c-dev", KERNEL=="i2c-[0-9]*", GROUP="i2c", MODE="0660"' \
  | sudo tee /etc/udev/rules.d/60-i2c-local.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=i2c-dev
```

Повторный вход в систему/SSH обязателен для новой группы. Проверить `id` и
`ls -l /dev/i2c-1`. Не использовать `chmod 777` и не запускать ROS через sudo.

### GPIO RP1, права и параметры

```bash
sudo apt install python3-libgpiod gpiod
sudo groupadd -f gpio
sudo usermod -aG gpio "$USER"
gpiodetect
gpioinfo
ls -l /dev/gpiochip*
```

`gpio_chip:=auto` ищет единственный контроллер с label `pinctrl-rp1` и проверяет
имена линий `GPIO17`/`GPIO27`. Номер `/dev/gpiochip4` **не фиксирован** и меняется
между ядрами. При необходимости задать подтверждённый путь явно. Поддерживаются
Python API libgpiod 1.x (Ubuntu 24.04) и 2.x. Ошибка доступа/занятая линия/другой
контроллер — отказ запуска, без скрытого перехода к четырёхпроводному режиму.

Если в системе нет штатных прав GPIO, правило ниже даёт группе `gpio` доступ ко
всем GPIO chips; включать в эту группу только доверенного оператора робота:

```bash
echo 'SUBSYSTEM=="gpio", KERNEL=="gpiochip*", GROUP="gpio", MODE="0660"' \
  | sudo tee /etc/udev/rules.d/60-gpio-local.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=gpio
# Затем выйти и войти заново, проверить id и ls -l /dev/gpiochip*.
```

Параметры отдельного драйвера: `gpio_chip:=auto rst_gpio:=17 int_gpio:=27`.
В `project_start start.launch.py`: `imu_gpio_chip:=auto imu_rst_gpio:=17
imu_int_gpio:=27`. Значения по умолчанию уже заданы. `rst_gpio/int_gpio` — смещения
линий в подтверждённом RP1 chip, совпадающие с BCM, **не** контакты 11/13.
Например:

```bash
ros2 launch project_start start.launch.py \
  imu_gpio_chip:=auto imu_rst_gpio:=17 imu_int_gpio:=27
```

### Обнаружение платы

**Остановить IMU-драйвер, Nav2 и любые другие программы на этой шине**;
силовая часть выключена. Однократно проверить только ожидаемые адреса:

```bash
i2cdetect -y -r 1 0x4a 0x4b
```

Обычно виден `4b`, после изменения ADR — `4a`. Этот probe не доказывает исправность
SHTP; драйвер выполнит аппаратный reset/handshake. Не выполнять `i2cdump`, `i2cset` или
циклическое сканирование работающего BNO086: это не обычный регистровый датчик.
`UU` означает занятость адреса kernel-драйвером, а не разрешение принудительно
обходить его. Пустая таблица — питание, земля, перемычки, адрес, контакты, kernel/overlay.

## 4. Сборка и очистка старого overlay

Удаление исходников не удаляет уже установленный старый ROS-пакет. Остановите
старые процессы/launch и systemd-сервис IMU, если создавали его вручную. Не
оставляйте два издателя `/imu/data` и старый USB-UART IMU подключённым «про запас».
Старые пользовательские udev-правила и systemd unit можно удалить вручную после
проверки, что они относятся только к прежней IMU; новый драйвер их не использует.

Откройте **новый терминал**, без source прежнего workspace в `.bashrc`, и выполните:

```bash
source /opt/ros/jazzy/setup.bash
cd ~/ros2_ws1909
rosdep install --from-paths src --ignore-src -r -y --rosdistro jazzy
# Если workspace ранее уже собирался, удалить ТОЛЬКО генерируемые каталоги:
# Сначала проверить pwd: здесь должен быть корень именно ros2_ws1909.
pwd
rm -rf -- build install log
colcon build --symlink-install
source install/setup.bash
ros2 pkg prefix bno086_imu
```

Исходники не удалять. Внешний YDLidar SDK всё ещё требуется для сборки его драйвера,
как описано в [GPS_NAVIGATION_RU.md](GPS_NAVIGATION_RU.md). Для изолированной
проверки одной IMU можно собрать `colcon build --symlink-install --packages-select bno086_imu`.
Зависимость `python3-smbus2` устанавливается apt/rosdep; Blinka/CircuitPython и
pip-установка в системный Python не нужны. Raw `I2C_RDWR` не имеет ограничения
SMBus block в 32 байта и не посылает фиктивный адрес регистра перед SHTP-пакетом.

## 5. Первый отдельный запуск

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws1909/install/setup.bash
ros2 launch bno086_imu imu.launch.py \
  i2c_bus:=1 i2c_address:=75 declination_deg:=0.0
```

0.0 — **пример синтаксиса, не правильное склонение для Москвы**. Подставить актуальное
значение для места/даты, восточное положительное. При использовании 0x4A задать
`i2c_address:=74`. Значения launch-адреса здесь десятичные.

В другом терминале с тем же окружением:

```bash
ros2 node list
ros2 topic info /imu/data --verbose
ros2 topic echo /imu/accuracy --qos-reliability best_effort
ros2 topic echo /diagnostics
ros2 topic hz /imu/data
ros2 topic echo /imu/data --once --qos-reliability best_effort
ros2 topic echo /imu/mag --once --qos-reliability best_effort
ros2 topic echo /imu/azimuth --once --qos-reliability best_effort
```

| Топик | Содержимое |
|---|---|
| `/imu/data` | `sensor_msgs/Imu`: quaternion, рад/с, м/с² |
| `/imu/mag` | `sensor_msgs/MagneticField`: **тесла**, не микротесла |
| `/imu/accuracy` | `std_msgs/UInt8`: качество Rotation Vector 0…3 |
| `/imu/azimuth` | `std_msgs/Float32`: азимут **X датчика**, градусы, 0 север, 90 восток |
| `/diagnostics` | возраст/качество Rotation Vector, оценка ошибки курса |

QoS измерений — SensorData/Best Effort. Сам узел TF не публикует. На столе можно
смотреть данные без URDF; для локализации нужны физически верные статические TF.

Если пока есть `/imu/accuracy`, но нет `/imu/data`, это может быть нормальное
ожидание калибровки. По умолчанию требуется accuracy≥2 и heading error≤0.35 рад.
Статусы SH-2: 0 unreliable, 1 low, 2 medium, 3 high. Это оценка датчика, не внешняя
гарантия истинного курса. Включён **Rotation Vector (0x05)**; Game Rotation Vector
(без абсолютной магнитной привязки) намеренно не поддерживается.

## 6. Калибровка, монтаж и географический курс

1. На первом этапе отключить приводы и держать плату вдали от магнитов/стали.
2. Дать ей полежать неподвижно, затем медленно повернуть в нескольких ориентациях
   по всем трём осям, описать «восьмёрку», снова оставить неподвижно.
3. Следить за `/imu/accuracy` и `heading_error_rad` в diagnostics; добиться устойчивого
   качества. Не заменять калибровку уменьшением `min_accuracy` до слабого решения.
4. Драйвер использует штатную динамическую калибровку SH-2; отдельная запись FRS/DCD
   во flash и фирменная interactive calibration BNO086 здесь **не реализованы**.
   Нет сервисов прежней платы `gyro_calib`, `zero_yaw`, `save_flash`.
   После отключения питания заново проверять качество; сохранение пользовательской
   калибровки этим кодом не обещается.
5. Жёстко закрепить плату; по возможности X вперёд, Y влево, Z вверх.
   Ориентироваться по нанесённым на **вашу плату** осям, а не по направлению Qwiic.
6. В `src/tracked_robot_description/urdf/tracked_robot.urdf.xacro` измерить и записать
   `imu_xyz` и `imu_rpy`. Старые координаты 0.135/−0.275/0.4 оставлены только как
   прежнее место установки; они не подтверждены для нового крепления.
   Размер визуальной платы обновлён, это не измерение реального корпуса.
7. Повторить измерения на собранном роботе с работающим лидаром и VESC, сначала
   с безопасно вывешенными гусеницами. Если курс меняется при подаче тока на моторы,
   перенести IMU/силовые провода. Не маскировать такую ошибку yaw_offset.

Для GPS quaternion должен иметь абсолютный **ENU**-курс:

| Направление X датчика при горизонтальной плате | yaw истинной ENU | `/imu/azimuth` |
|---|---:|---:|
| Географический восток | 0 | 90° |
| Географический север | +π/2 | 0° |
| Географический запад | ±π | 270° |
| Географический юг | −π/2 | 180° |

Поворот влево вокруг Z вверх даёт положительный `angular_velocity.z`.
Для горизонтальной платы Z вверх ускорение покоя около +9.81 м/с² по Z:
это **calibrated accelerometer с гравитацией**, не gravity-removed report.
Поле обычно порядка десятков микротесла (порядка 10⁻⁵ Тл), но само по себе
правдоподобное значение не доказывает отсутствие магнитного искажения.

### Склонение: где и с каким знаком

Считаем BNO086 Rotation Vector ориентацией sensor→**magnetic ENU**.
Если D — восточно-положительное склонение магнитного севера от истинного:

```text
yaw_true_ENU = yaw_magnetic_ENU - D
q_true = quaternion_z(-D) × q_magnetic
```

Например, при D=+10° X, направленный на магнитный север, имеет истинный ENU yaw
+80°, а его истинный азимут равен 10°. Это не смена осей измеренного гироскопа,
поэтому accel/gyro/mag остаются в `imu_link`; поправляется только мировая система
quaternion. Монтаж платы относительно шасси задаётся **только URDF**.

`declination_deg` задаёт именно этот D драйверу в градусах. В
`project_start/config/localization.yaml` у navsat_transform оставить
`magnetic_declination_radians: 0.0`, `yaw_offset: 0.0`. Не добавлять склонение
второй раз в EKF/navsat, не переносить вслепую прежнюю монтажную поправку.

Для проверки направлений нужен независимый географический ориентир/измерение,
не только компас телефона рядом с моторами. Если четыре направления не сходятся,
**не запускать AUTO**: проверить оси платы, TF, фактическую конвенцию quaternion
конкретной firmware, знак склонения и окружающее поле.

## 7. Общий запуск робота

Остановить отдельный `bno086_imu imu.launch.py`. Затем:

```bash
# Терминал 1, заменить 0.0 измеренным/расчётным местным склонением:
ros2 launch project_start start.launch.py \
  imu_i2c_bus:=1 imu_i2c_address:=75 declination_deg:=0.0 \
  gps_port:=/dev/ttyAMA2 lidar_port:=/dev/ttyUSB0

# Терминал 2:
ros2 launch project_start localization.launch.py

# Терминал 3:
ros2 launch project_start navigation.launch.py
```

Проверить `ros2 topic info /imu/data --verbose`: должен быть **один** publisher.
Новый драйвер использует cooperative flock на I²C-адаптере, чтобы две его копии
не сбрасывали друг другу BNO086. Это не защищает от `i2cdetect` и других программ,
не использующих flock. Во время работы IMU не сканировать шину.

Локальная одометрия совмещает yaw BNO086 и аппаратные счётчики по времени
([подробности](ODOMETRY_RU.md)). Глобальный EKF берёт yaw и wz из `/imu/data`; ускорение не включено в
fusion, флаг `imu0_remove_gravitational_acceleration: false` поэтому не мешает.
Не добавляйте внешний фильтр Madgwick поверх уже fused Rotation Vector.
Перед заменой/сменой склонения/монтажа остановить миссию и **перезапустить
counter_odometry, глобальный EKF и navsat_transform**, поскольку их предыдущие состояния/геопривязка уже неверны.

Маршрут и настройка Nav2 остаются по [основной инструкции](GPS_NAVIGATION_RU.md).
Изменение датчика не отменяет обязательные испытания на закрытой площадке.

## 8. Параметры и поведение при отказе

Конфиг: `src/bno086_imu/config/imu.yaml`. Параметры read-only: изменения требуют
перезапуска узла, чтобы в движении нельзя было незаметно повернуть мировой курс.
Отдельный launch принимает `params_file:=/absolute/path/imu.yaml`; его аргументы
`i2c_bus`, `i2c_address`, `declination_deg` имеют приоритет над файлом.
Общий hardware launch читает штатный config и переопределяет эти же три значения
аргументами с префиксом `imu_` для bus/address.

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `i2c_bus` | 1 | `/dev/i2c-N` |
| `i2c_address` | 75 | 0x4B; альтернативный 74 |
| `rate_hz` | 25.0 | accel/gyro/Rotation Vector |
| `mag_rate_hz` | 10.0 | диагностическое магнитное поле |
| `frame_id` | imu_link | оси физического датчика |
| `declination_deg` | 0.0 | восточно-положительное склонение, настроить обязательно |
| `sample_max_age` | 0.10 с | возраст каждого компонента плюс report delay |
| `reconnect_timeout` | 2.0 с | отсутствие новых обязательных reports → выход с ошибкой |
| `min_accuracy` | 2 | минимальный статус Rotation Vector |
| `max_heading_error` | 0.35 рад | предельная оценка ошибки курса |
| `orientation_stddev` | 0.05 рад | нижняя граница ковариации, увеличивается оценкой heading error |
| `angular_velocity_stddev` | 0.02 рад/с | настроить по шуму гироскопа |
| `linear_acceleration_stddev` | 0.15 м/с² | настроить по измерениям |
| `magnetic_stddev` | 2e−6 Тл | настроить по измерениям |

Оценка heading error SH-2 не является строгим Gaussian sigma; использование её
как нижней границы covariance — консервативная эвристика. Для серьёзной настройки
измеряйте реальные ошибки и корреляции. 25 Гц — запрошенная частота, не обещание
строго 25 сообщений/с: нужны новые accel, gyro, quaternion в одной свежей группе.

- Повторные/старые report sequence не освежают датчик, численно одинаковые **новые**
  измерения неподвижной платы допустимы.
- При плохой точности `/imu/data` прекращается, но accuracy/mag/diagnostics
  помогают калибровке. Не происходит бесконечных reset только из-за accuracy=0.
- При отсутствии обязательного отчёта, ошибке I²C, неожиданном reset, переполнении
  очереди или неподдерживаемом формате измерения прекращаются, ошибка
  защёлкивается в `/diagnostics` (ERROR). Автосброса и launch respawn **нет**.
  После устранения причины остановить робот и перезапустить hardware,
  localization и navigation, чтобы не соединять курс до/после reset.
  При ошибке инициализации процесс завершается без автоповтора.
- При потере `/imu/data` существующий `navigation_guard` запрещает AUTO примерно
  по своему `imu_timeout=0.3` с. Не путать 2 с reconnect timeout с временем stop.
  После fault IMU нужен описанный выше перезапуск стека на стоянке,
  затем проверка→AUTO и новая миссия. MANUAL→AUTO само по себе ошибку не снимает.
- Ограничение основного polling: задержка >0.2 с или долгая очередь вызывает
  остановку, а не выдачу старых пакетов с текущей датой.
- Метки ROS — оценка времени приёма на Pi с вычетом возраста компонентов/report
  delay. Base timestamp SH-2 разбирается как поле протокола, но полная привязка
  тактов датчика к UTC и GPIO-метка INT **не реализованы**. Batching отключён.
  Для высокодинамичной платформы нужна более точная синхронизация и её проверка.

## 9. Ограничения I²C на реальном Pi 5

SparkFun отдельно предупреждает о чувствительности BNO086 к I²C timing и не
рекомендует Qwiic Mux. Нельзя обещать совместимость любого kernel/кабеля/нагрузки
RP1 только потому, что адрес виден в `i2cdetect`.

При `Remote I/O error`, timeout, `header changed`, повторных reset:

1. Проверить питание 3.3 В под нагрузкой, общую землю, кабель и адрес.
2. Убедиться, что работает один клиент, на GPIO нет UART-конфликта.
3. Вернуться к 100 кГц и 25/10 Гц, без HAT/mux/других I²C нагрузок.
4. Проверить актуальное поддерживаемое ядро Ubuntu для Pi 5 и реальную
   конфигурацию RP1 I²C, сообщения `dmesg`.
5. При необходимости измерить SDA/SCL логическим анализатором, clock stretching,
   длительность транзакций и фронты. Не переносить старые инструкции GPIO-драйверов
   BCM283x на RP1 без проверки.
6. Если надёжность не достигнута — **не разрешать автономию**. Потребуется
   проверенное решение интерфейса/контроллера; SPI возможен как отдельная
   будущая доработка, текущий драйвер реализует только I²C по вашему запросу.

Физически зависшую шину даже аппаратный RST может не восстановить: иногда требуется
отключение питания датчика/робота. Не увеличивать watchdog до секунд ради
маскировки ошибок — это увеличивает время движения без актуального курса.

## 10. Приёмка и тесты

Перед автономным запуском:

- Проверить анализатором RST LOW→HIGH при старте и INT LOW перед чтениями.
- На безопасном стенде проверить отсутствующий INT, недоступный GPIO, второй
  экземпляр драйвера и неожиданный reset: нет устаревших `/imu/data`, AUTO
  запрещается, данные не возобновляются без явного перезапуска стека.
- Не менее 15–30 минут непрерывных данных под реальной нагрузкой CPU и шины;
  следить за частотой, качеством, diagnostics, перезапусками.
- Проверка четырёх направлений и поворота с выключенными/включёнными моторами.
- Проверка величин и единиц accel/gyro/mag; TF монтажа не зеркальный.
- Безопасная остановка драйвера/отключение IMU на стенде должна прекратить
  разрешение движения. Не выдёргивать провод питания на движущемся роботе.
- Проверка, что восстановление IMU не возобновляет старую миссию самопроизвольно.
- Повторить испытания GPS-маршрута и объезда с малой скоростью.

Проверки без ROS/железа:

```bash
python3 -m compileall -q src
PYTHONPATH=src/bno086_imu:src/project_start:src/cmd_switcher \
  python3 -m pytest -q src/bno086_imu/test \
  src/project_start/test/test_navigation_safety.py src/cmd_switcher/test/test_policy.py
```

Покрываются формат/масштабы SH-2, Q14 quaternion и Q12 heading error, порядок
компонент, ENU/склонение, последовательности/свежесть, fake-I²C и GPS/mux regression.
**В среде разработки нет ROS 2, Pi 5 и BNO086: реальная colcon-сборка, I²C и
географический курс на плате пока не проверены.**

## Диагностика тайм-аута INT после сброса

Доступна [отдельная стендовая утилита](BNO086_DIAGNOSTIC_RU.md): наблюдает INT без
паузы 300 мс после RST, проверяет оба адреса отдельными попытками и выполняет
raw SHTP/Product ID обмен даже при INT HIGH. Без ROS, без публикации IMU,
только на стоянке с отключёнными моторами и другими клиентами шины.
